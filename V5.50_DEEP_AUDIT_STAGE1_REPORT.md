## Remaining priority findings — Stage 2+
1. **City Atlas completeness is not finished.** There are 96 city records, but 30 lack `populationYear`, and 72 lack `geography`, while 72 lack `heritage`. These fields must be completed from traceable city-level sources rather than filled with guesses.
2. **Five-language content is not yet fully populated.** Missing translation attributes remain in some deep music/food content: FA 12, TR 116, AR 12. Stage 1 prevents leakage, but Stage 2 should supply real translations rather than English fallback.
3. **Version metadata had stale V5.42 references.** The live HTML metadata is now V5.50, but historical audit files inside the package still contain older version names; these should be clearly marked as archival rather than mistaken for the current build.
4. **Image/licensing audit remains necessary.** The site contains remote images from multiple domains. The academic rights policy exists, but a final release should have a machine-readable image register with source page, creator, licence, access date and commercial-use status for every externally hosted image.
5. **External-link verification is not complete.** There are many external academic/source links. A final release pass should check HTTP status and redirect behavior for all of them.
6. **Live GitHub Pages QA is still required.** Static local QA cannot prove the deployed GitHub Pages build, mobile browser rendering, remote image loading, console errors, HTTPS/mixed-content behavior or real network speed.
7. **Launch-date wording needs editorial care.** The approved project launch date remains 11 March 2027. Official KRG calendars list National Clothing Day on 10 March, so the site should not state that 11 March is the exact same-day National Clothing Day date. The approved launch date itself was not changed.
8. **Card-content boundary needs one final duplicate audit.** The structural container is correct, but cross-card duplication should be checked at the content-claim level, especially History vs Places, Culture vs Community, and Religion vs Culture.
9. **SEO can be improved further.** The current site has title, description, canonical, OG/Twitter metadata and basic JSON-LD, but the 16 card details are dynamically modal-driven rather than individual crawlable URLs. A later stage should decide whether dedicated shareable section URLs are needed without breaking the current card UX.
10. **Performance needs real-device validation.** Lazy loading/defer are present, but the HTML is still very large (~1.1 MB) and many remote images/data records are embedded. A real Lighthouse/mobile pass is needed before calling performance final.
